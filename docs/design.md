# 설계

## 목표

서버 없이 Next.js 하나로, 11기·12기 태그가 붙은 사람들의 위키 글을 "마을에서 만나 말을 거는" 방식으로 읽게 한다.

## 데이터 흐름

```
원본 DB (Django CSV 덤프, 저장소 밖)
   │  scripts/build-data.mjs  ← 사람이 직접 실행, 빌드 파이프라인에는 없음
   ▼
src/data/generated/people.json + public/wiki-images/*.webp   (커밋됨)
   │  import
   ▼
src/lib/people.ts ──▶ src/lib/village.ts (배치 계산) ──▶ 3D 씬 / UI
```

런타임에 네트워크 요청으로 받아 오는 데이터는 없다. 페이지는 전부 정적으로 프리렌더된다.

### 누가 들어가는가

| 단계 | 기준 | 결과 |
|---|---|---|
| 전체 문서 | `documents_currdoc` | 222 |
| 11기 또는 12기 태그 | `documents_generation` | 203 |
| 그중 사람 | 기수 문서(`N기`)의 인물 표에 링크된 제목 + `EXTRA_PEOPLE` | **136** |

DB의 기수 태그는 실제 소속과 다르다(14기 아기사자 문서에 9~12기 태그가 붙어 있는 식). 그래서 **선별은 태그로**, **마을 배치는 인물 표에서 읽은 소속 기수·파트로** 한다.

알려진 한계: 11기 인물 표에 있지만 태그가 `10기`뿐인 문서(박경빈, 한윤호)와 9기·10기 태그만 있는 문서는 규칙대로 빠진다. 넣으려면 `EXTRA_PEOPLE`에 추가한다.

## 마을

- 광장(원점)을 중심으로 기수 마을 6곳이 둘러싼다. 입장하면 11기·12기 마을이 정면 좌우에 있다.
- 마을 안에서는 사람들이 동심원으로 서고, 같은 파트끼리 이웃한다. 옷 색 = 파트, 마을 색 = 기수.
- 배치는 시드 고정 난수로 계산하므로 언제 접속해도 같은 사람이 같은 자리에 있다.

## 렌더링

| 대상 | 방식 | 드로우콜 |
|---|---|---|
| 주민 136명 | `InstancedMesh` 2개 (몸 / 옷) | 2 |
| 이름표 | 캔버스 텍스처 스프라이트, 44 유닛 밖은 숨김 | 보이는 수만큼 |
| 집·나무·구름 | `InstancedMesh` | 4 |
| 플레이어 | 팔다리가 따로 움직이는 mesh 7개 | 7 |

- 외부 모델 파일 없음. 사자는 구버전 픽셀 마스코트를 상자로 옮긴 것.
- 물리엔진 없음. 충돌은 전부 원 대 원.
- 매 프레임 바뀌는 값(위치, 입력, 카메라)은 React 상태가 아니라 `src/lib/store.ts`의 plain object. React가 구독하는 것은 "가까운 주민", "열린 글", "명부 열림", "길 안내 대상"뿐이다.

## 본문 렌더링

`react-markdown` → `remark-gfm`, `remark-breaks`(원본 뷰어가 줄바꿈을 그대로 보여 줬다) → `rehype-raw` → 이미지 폭 보존 → `rehype-sanitize`.

- 원문의 `<img style="width: 30%">`는 sanitize가 style을 지우므로, 그 전에 숫자만 `data-width`로 옮겨 살린다.
- `#wiki/<이름>` 링크는 아카이브에 그 사람이 있으면 그 글로 넘어가는 버튼, 없으면 점선 밑줄 텍스트.

## 3D를 못 쓰는 경우

WebGL이 없으면 안내 문구와 함께 주민 명부만으로 모든 글을 읽을 수 있다.
