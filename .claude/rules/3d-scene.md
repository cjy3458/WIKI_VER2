# 3D 씬 규칙

## 컨셉 (바꾸지 말 것)

기획은 `docs/world-design.md`. 구버전 위키의 "파란 모눈 위 브라우저 창 속 픽셀 세계"를 3D로 옮긴 공간이다.

- **둥근 것이 없다.** 섬·광장·길·나무·집·구름·고리 전부 네모(블록)다. 원기둥·구·원형 평면을 쓰지 않는다. 길은 격자 방향으로만 뻗는다.
- 하늘을 그리지 않는다. 캔버스는 투명(`gl.alpha`)이고 뒤의 CSS 파란 모눈(`.desktop`)이 하늘이다. `scene.background`, 안개를 넣지 않는다.
- 색·질감은 구버전 그림에서 온 것: 파랑 `#4c4df5`, 잔디 두 톤, 흙벽돌, 물, 사자 노랑/갈기 주황, 검은 테두리와 딱딱한 그림자.
- 픽셀 질감은 `pixelTexture()`(문자열 픽셀 맵 → NearestFilter 텍스처)로 만든다. 이미지 파일을 추가하지 않는다.
- 글자(이름표·표지판·말풍선·타워 화면)는 둥근모 폰트(`--font-pixel`)로 캔버스에 그린다.
- 이름표가 읽혀야 하므로 화면 전체를 저해상도로 뭉개는 방식(dpr 낮추기, 픽셀화 후처리)은 쓰지 않는다.

## 구조

- `<Canvas>`는 `src/components/world/World.tsx` 한 곳. 페이지에서는 `next/dynamic(..., { ssr: false })`로 불러온다.
- 배치(주민, 집, 나무, 길, 건축물 좌표, 장치, 충돌체)는 `src/lib/village.ts`가 계산한다. 시드 고정 난수를 써서 새로고침해도 같은 자리에 같은 사람이 서 있어야 한다. `Math.random()` 금지.
- 건축물은 `landmarks`에 좌표로 정의하고, 주민·집·나무 배치는 그 자리와 길을 피한다. 건축물을 추가하면 `reserved`와 `colliders`에도 넣는다.
- 외부 3D 모델 파일(GLB)은 쓰지 않는다. 전부 상자로 만든다.

## 배치

- **기수별 구역을 만들지 않는다.** 11기·12기 태그를 둘 다 가진 사람이 많아서 사용자가 구역 구분을 없애라고 했다. 주민은 섬 전체에 기수·파트와 상관없이 흩어 세운다.
- 이름으로 찾아 **그 사람 바로 앞으로 순간이동**할 수 있어야 한다(`useGame().teleportTo`, `spotNear`).
- `Space`로 쓰는 장치(`spots`): WIKI 타워 앞 터미널 → 주민 찾기 창, 랜덤 포털 → 아무 주민 앞으로 이동.

## 사자가 가려지지 않게 (사용자 요청)

나무·집·표지판이 사자를 가리면 불편하다. 풍경을 추가할 때 아래 장치들이 깨지지 않게 한다.

- **나무·집은 적게**: 집 12채, 나무 64그루. 시야를 가리는 나무·집을 낮추는 방식(cutaway)은 판정이 어색하다는 사용자 피드백으로 없앴다. 다시 넣지 말고, 가려지면 수를 줄이거나 자리를 옮긴다.
- **비쳐 보이기**: 그리는 순서가 풍경(0) → 실루엣(1) → 사자(2) → 이름표(5)다(`RENDER_ORDER`). 실루엣은 `depthFunc: GreaterDepth`라 풍경 뒤에 있는 부분만 그려진다. **풍경에 `renderOrder`를 주거나 투명 재질(`transparent`)의 큰 물체를 넣으면 이 순서가 깨진다.**
- **이름표**는 `depthTest: false`로 항상 맨 위에 그린다.
- **건축물 표지판**은 작게, 그리고 가까이 가면 흐려진다.

## 성능 (NPC가 60명 안팎이다)

- NPC, 나무, 집처럼 반복되는 것은 반드시 `InstancedMesh`. NPC 한 명당 mesh를 여러 개 만드는 방식 금지.
- 이름표는 DOM(`<Html>`)이 아니라 캔버스 텍스처 스프라이트. 멀리 있는 이름표는 숨긴다.
- `useFrame` 안에서 `setState` 금지, 객체 새로 만들기(`new Vector3()`) 금지 — 모듈 스코프 임시 객체를 재사용한다.
- 매 프레임 바뀌는 값(플레이어 위치 등)은 ref나 zustand의 `getState()`로 읽는다. React 상태로 구독하는 것은 "가까운 NPC가 누구인지", "열린 문서가 무엇인지"처럼 드물게 바뀌는 값뿐이다.
- **같은 높이에 면을 겹치지 않는다.** 섬 윗면은 y=0이다. 그 위에 얹는 면(길·광장·물)은 0.1 이상 띄우고 서로도 0.1 이상 차이를 둔다. 윗면이 y=0인 상자를 추가하면 화면이 깜빡인다(z-fighting, 실제로 낸 버그).
- 그림자용 조명은 플레이어를 따라가되 8 단위로 끊어 옮긴다. 매 프레임 따라가면 그림자 가장자리가 떨린다.
- 해는 구버전 창 그림의 해를 블록으로 옮긴 3D 물체(`Sun`)다. 화면에 고정한 이미지로 두면 "그냥 떠 있는 것 같다"는 피드백을 받았다. 카메라 위치를 따라가며 늘 같은 방향(입장 시 정면 오른쪽, 수평선보다 조금 위) 하늘에 있고, 시점을 돌리면 화면에서 움직인다. 기본 시점 기울기(`pitch 0.32`)를 높이면 해가 화면 밖으로 나간다.
- 그림자는 방향광 하나만. `dpr`은 `[1, 2]`로 제한.

## 조작

- 이동: **방향키만** (카메라 기준). WASD는 쓰지 않는다 — 사용자가 방향키로 바꾸라고 했다. 모바일: 화면 조이스틱.
- 대화: NPC 반경 안에서 **`Space`** 또는 화면 버튼. 주민이 없고 장치(터미널·포털) 앞이면 `Space`가 그 장치를 쓴다. `E`는 쓰지 않는다.
- 채팅: `Enter`로 입력창에 들어가고 다시 `Enter`로 보낸다. 입력 중에는 방향키·`Space`가 캐릭터에 전달되지 않아야 한다. 문서가 열려 있는 동안은 이동 입력을 무시한다.
- 카메라: 드래그로 회전, 휠/핀치로 줌. 플레이어를 따라간다.
- 충돌은 물리엔진 없이 원 대 원으로 직접 처리한다. 섬 가장자리는 정사각형(`WALK_HALF`)으로 막는다.

## 접근성

- WebGL이 없거나 3D가 부담스러운 사용자를 위해 **주민 찾기**(이름 목록 → 글 바로 열기)를 항상 제공한다. 3D는 탐색 방식이지 유일한 진입로가 아니다.
